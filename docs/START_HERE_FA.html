پروژهٔ SCARA: تحویل، فهم پژوهش و اجرای کد

نسخهٔ اصلاح‌شده پس از داوری — ۷ اکتبر ۲۰۲۶. این راهنما برای خواندن بدون اینترنت ساخته شده است. نصب اولیهٔ وابستگی‌ها به اینترنت نیاز دارد.

۱. دقیقاً چه چیزی را پژوهش می‌کنیم؟

یک ربات SCARA چند جسم با جرم و اینرسی یکسان را جابه‌جا می‌کند، اما ابتدا این دو پارامتر را نمی‌داند. ربات هنگام کار معمولی هم از اندازه‌گیری‌ها یاد می‌گیرد. سؤال این است: آیا انجام یک حرکت اضافی مچ برای شناسایی بار، آن‌قدر زمان کارهای بعدی را کم می‌کند که هزینهٔ خودش جبران شود؟

«پروب» همان حرکت اضافی ۰٫۶ رادیانی مچ و برگشت آن است. «یادگیری منفعل» یعنی تخمین پارامترها از حرکت‌های عادی و نگه‌داشتن بار. «batch-aware» زمان باقی‌مانده و یادگیری احتمالی آینده را پیش‌بینی می‌کند تا دربارهٔ پروب تصمیم بگیرد.

نتیجهٔ اصلی نسخهٔ اصلاح‌شده: در تنظیمات اولیه، میانگین هزینهٔ پروب حتی در دسته‌های ۱۰۰‌تایی جبران نشد؛ با این حال، ۴ مورد از ۲۷ سناریوی موفقِ کم‌چرخش از آن سود بردند و قاعدهٔ تصمیم این فرصت‌ها را از دست داد. اما در مسیر کم‌چرخش با نویز ده برابر و دستهٔ ۶۰‌تایی، حدود ۱٫۰۵ ثانیه صرفه‌جویی کرد و قاعدهٔ تصمیم آن را انتخاب کرد. در نزدیکی مرز سود و زیان، تصمیم‌ها کاملاً درست نیستند؛ این محدودیت در مقاله گزارش شده است.

۲. وضعیت سه فاز

سه فاز نسخهٔ محاسباتی تکمیل شده‌اند: ۳ از ۳.

فازخروجیوضعیت
۱. ممیزی و طراحیتطبیق نقد با کد، اصلاح واحدها، بررسی منابع و ثبت پروتکلتکمیل
۲. اجرا و ارزیابی۶۰۵۰ اجرای تکمیلی، نقطهٔ تغییر علامت، حساسیت، اصطکاک و کیفیت تصمیمتکمیل

این نوار، پیشرفت نسخهٔ محاسباتی را نشان می‌دهد. ارسال به کنفرانس، تعیین نویسندگان، انتخاب مجوز انتشار و تطبیق قالب مقصد هنوز انجام نشده است. دادهٔ سخت‌افزاری نداریم.

۳. باز کردن پروژه در VS Code

  1. فایل ZIP را کامل Extract کنید. فایل‌ها را از داخل ZIP اجرا نکنید.
  2. در VS Code گزینهٔ File → Open Folder را بزنید.
  3. پوشهٔ SCARA_Research_Revision1 را انتخاب کنید؛ پوشه‌ای که revision.py، run.py و requirements.txt داخل آن هستند.
  4. از منوی Terminal → New Terminal ترمینال را باز کنید.
  5. دستورهای بخش مناسب سیستم‌عامل خود را در همان ترمینال اجرا کنید. اجرای مدل با دکمهٔ Run روی یک فایل داخلی توصیه نمی‌شود؛ نقطهٔ ورود پروژه مشخص است.

۴. نصب و اجرای اولیه در Windows

پایتون ۳٫۱۲ توصیه می‌شود. در PowerShell:

py -3.12 --version
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py demo --out demo_output

در این روش نیازی به فعال‌سازی محیط مجازی یا تغییر Execution Policy نیست؛ مفسر همان محیط مستقیماً اجرا می‌شود. خروجی دمو برای هر روش موفقیت، زمان و تعداد پروب را چاپ می‌کند. در اولین اجرا کامپایل Numba کمی زمان می‌برد.

۵. نصب و اجرای اولیه در Linux یا macOS

python3.12 --version
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py demo --out demo_output

اجرای این نسخه در محیط Linux بررسی شده است. دستورهای Windows و macOS راهنمای استفاده‌اند و آزمون اجرایی روی آن دو سیستم انجام نشده است.

۶. بازتولید تحلیل و شکل‌ها بدون اجرای دوبارهٔ شبیه‌سازی

در Windows:

.venv\Scripts\python.exe revision.py analyze
.venv\Scripts\python.exe revision.py verify
.venv\Scripts\python.exe revision.py progress

در Linux/macOS:

.venv/bin/python revision.py analyze
.venv/bin/python revision.py verify
.venv/bin/python revision.py progress

دستور analyze از CSVهای تحویلی استفاده می‌کند و شکل‌ها، جدول‌های LaTeX و تحلیل‌های آماری را بازسازی می‌کند. دستور verify باید PASS بدهد. دستور progress تعداد اجراهای ثبت‌شده را نشان می‌دهد. این مسیر برای شروع، سریع‌تر و مناسب‌تر از اجرای کل آزمایش است.

۷. اجرای دوبارهٔ تمام آزمایش‌های اصلاحیه

# Windows
.venv\Scripts\python.exe revision.py rerun

# Linux / macOS
.venv/bin/python revision.py rerun

این فرمان ابتدا از CSVهای موجود در پوشهٔ rerun_backups نسخهٔ زمان‌دار می‌گیرد، سپس ۵۸۰۰ اجرای پروتکل اصلی اصلاحیه و ۲۵۰ اجرای بررسی دقیق‌تر مرز را انجام می‌دهد و تحلیل‌ها را بازسازی می‌کند. زمان اجرا به رایانه وابسته است؛ پنجره را تا پایان نبندید. زمان محاسبات برنامه‌ریز می‌تواند بین رایانه‌ها فرق کند.

برای آزمون‌های عددی تکمیلی:

# Windows
.venv\Scripts\python.exe -m src.revision_validation

# Linux / macOS
.venv/bin/python -m src.revision_validation

۹. آموزش فشردهٔ منطق کد

  1. نمونه‌سازی: seed بار واقعی و مسیر را تعیین می‌کند. برای انصاف، روش‌ها همان سناریو و جریان نویزِ هر قطعه را دریافت می‌کنند.
  2. کنترل: کنترل‌کننده با تخمین جرم و اینرسی گشتاور می‌سازد. ربات شبیه‌سازی‌شده پارامتر واقعی دارد.
  3. یادگیری: هر ۵۰ میلی‌ثانیه، اندازه‌گیری نیرو و تغییر سرعت تخمین را به‌روزرسانی می‌کند. نیروی نگه‌داشتن بار هم برای جرم مفید است.
  4. زمان‌بندی: مدت انتقال با غربال محدودیت‌ها و یک حاشیهٔ ابتکاری وابسته به عدم‌قطعیت انتخاب و به گام‌های ۲۵ میلی‌ثانیه گرد می‌شود.
  5. تصمیم: پس از اولین گرفتن، قاعده دو آینده را مقایسه می‌کند: ادامهٔ کار با یادگیری معمولی، یا یک پروب و سپس ادامهٔ کار.
  6. ارزیابی: زمان واقعی شبیه‌سازی، شکست‌ها، تعداد اقلام کامل‌شده و خطای تصمیم ذخیره می‌شوند.

برای فهمیدن کد از revision.py شروع کنید، بعد تابع batch در revision_experiment.py، سپس توابع segment، schedule و probe_decision را در model_r1.py بخوانید.

۱۰. تفسیر درست عددها

  • Probe minus passive: مثبت یعنی پروب زمان بیشتری گرفته؛ منفی یعنی صرفه‌جویی کرده است.
  • Regret: اختلاف هزینهٔ تصمیم انتخاب‌شده با بهترینِ دو اقدام در همان سناریو پس از دیدن نتایج. کمتر بهتر است؛ این مقایسه‌گر در زمان تصمیم در دسترس ربات نیست.
  • CI: فاصلهٔ bootstrap از بازنمونه‌گیری seedهای جفت‌شده. اقلام متعدد یک دسته، نمونه‌های مستقل نیستند.
  • موفقیت مشروط: زمان میانگین فقط بین دسته‌های کامل‌شده با تعداد شکست‌ها خوانده می‌شود. شکست را نباید تولید سریع تلقی کرد.
  • عدم‌قطعیت: کوچک شدن مقدار P الزاماً به معنای خطای واقعی کمتر یا ایمنی نیست. اصطکاک ناشناخته می‌تواند تخمین را بایاس کند.

۱۱. اگر خطا دیدید

خطااقدام
No module named numbarequirements را با همان مفسری نصب کنید که اجرای پروژه را انجام می‌دهد؛ از مسیر محیط مجازی بالا استفاده کنید.
Can't open file revision.pyترمینال در ریشهٔ پروژه نیست. پوشهٔ حاوی revision.py را باز کنید.
ModuleNotFoundError: srcفایل داخلی src را مستقیم اجرا نکنید؛ از revision.py یا دستور python -m استفاده کنید.
توقف ظاهری در اولین اجراممکن است کامپایل اولیهٔ Numba باشد؛ خروجی و مصرف CPU را بررسی کنید.
خطای hash پس از ویرایش کدپروتکل عمداً تغییر کد منجمد را تشخیص می‌دهد. نسخهٔ تحویلی را برای بازتولید نگه دارید و آزمایش تازه را در کپی جدا، با پروتکل جدید انجام دهید. hash قدیمی را برای پنهان‌کردن تغییر عوض نکنید.

۱۲. ساخت PDF و کار حرفه‌ای با Git

PDF آماده در بسته هست. برای ویرایش متن و ساخت دوباره، یک توزیع LaTeX و latexmk لازم است؛ از ریشهٔ پروژه:

cd paper
latexmk -pdf -interaction=nonstopmode -halt-on-error manuscript.tex

کد، پروتکل‌ها، مستندات، فایل bib و منبع مقاله را از همین حالا در مخزن خصوصی نسخه‌بندی کنید. محیط .venv، cacheها و فایل‌های موقت را commit نکنید. داده‌های خام را به‌صورت نسخهٔ ثابت آرشیو کنید؛ اگر اندازه زیاد شد، از release artifact یا ابزار مناسب فایل‌های بزرگ استفاده کنید. قبل از تغییر تنظیمات یک commit مشخص داشته باشید و تحلیل‌های اکتشافی را از ارزیابی اولیه جدا نگه دارید. در این تحویل هیچ مخزن عمومی ایجاد نشده است.

برای ارسال واقعی هنوز مقصد، نویسندگان و وابستگی سازمانی، مجوز کد و الزامات افشا/قالب همان کنفرانس باید مشخص شوند. این بسته یک مطالعهٔ شبیه‌سازی با سهم روش‌شناختی محدود است؛ پذیرش کنفرانس یا اعتبارسنجی سخت‌افزاری را تضمین نمی‌کند.
